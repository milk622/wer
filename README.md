# 健身日历

一个零依赖、简体中文、深色主题的个人健身记录 PWA。原生 HTML、CSS 和 JavaScript，无需构建、账号、数据库或应用业务服务器。GitHub Pages 仅托管静态文件，训练数据留在各自手机 localStorage 中。

## 最快开始

1. Windows 右键下载的 ZIP →「全部解压」。
2. 按随附《部署与手机安装教程.md》把本文件夹内容上传到 GitHub，并启用 Pages。
3. 两个人分别用手机打开同一个 HTTPS 网址，添加到主屏幕。
4. 从桌面图标打开，选择日期和训练部位，点击「保存训练」。首次联网等底部显示「离线资源已就绪」再测试断网。

不要直接双击 index.html 来验证 PWA。file:// 不支持正常 Service Worker，存储行为也可能不同。部署不需要 Node、npm 或 Python。

## 功能与使用

- 月历以周一开始，默认当天。箭头切换月份，「今天」回到当天；绿色小点表示该日有记录，圆框表示今天。
- 点击日期，在下方多选训练部位并保存；同一天仅一条记录，多部位只算一个训练日。支持补录和未来日期手动记录。
- 再点已选项目可取消；修改后再次保存。休息日不保存记录；清空选择不能误删记录，删除请使用「删除当天记录」并确认。
- 自定义名称1–20字，最多100个；添加后自动选中，再点击保存训练。项目名称按纯文本显示。
- 顶部显示当前浏览月份训练天数和历史累计天数，切换月份后统计随之改变。
- 统计 / 备份 → 导出 JSON。导入会校验格式、日期、项目名称与版本，确认后替换全部记录和自定义项目，不合并。失败保留原数据。文件最大5MB。
- 损坏的本地数据不会被静默覆盖；可导出原始数据留存，然后导入有效备份恢复。浏览器禁止存储或容量不足会显示保存失败。

## 数据与隐私

数据键为 `fit-calendar.data.v1`。日期使用本机年月日拼接，不用 UTC ISO 日期切片；仅备份生成时间采用 ISO 时间戳。更改设备时区不会重写既有记录。

记录格式示例：

```json
{
  "app": "fit-calendar",
  "version": 1,
  "records": {"2026-10-22": ["胸部", "三头"]},
  "customProjects": []
}
```

两部手机没有同步。同一设备不同浏览器、隐私模式或桌面 Web App 的存储环境也可能不同，建议先安装，再固定从同一个桌面入口使用。清理网站数据、系统回收、换手机可能使本地数据丢失。建议每周及换机前备份；iPhone 导出后检查「文件」App的下载位置或系统保存界面。JSON是明文，请自行保管。不要把个人备份上传到公开仓库。

程序没有分析统计、广告、联网字体或外部脚本，不上传训练记录。首次加载和检查新版本会请求静态网站资源，托管方仍可能记录常规网络访问日志。

## 离线与更新

Service Worker 成功安装时一次缓存10个必要资源；安装缓存失败不会显示离线已就绪。相对路径兼容 `/仓库名/`。资源按版本从缓存读取，避免一组资源混用新旧版本。

发布更新：先在 `sw.js` 把 VERSION 从 `v1.0.0` 改为新版本号，再一起上传所有修改文件。联网打开或回到应用时检查更新，出现「新版本已就绪」后点击「更新应用」。未保存选择会询问是否放弃；已保存记录保持不变。只清理当前应用范围内旧静态缓存，不操作 localStorage。更新后重新检查一次离线打开。

## 本地预览与开发测试（可选）

普通用户直接部署即可。开发者如已安装 Python，可在本文件夹打开终端运行 `python -m http.server 8080`，在本机浏览器访问 `http://localhost:8080/`。这只是本地测试工具，不是应用运行所需的后端；手机通过局域网HTTP访问不满足 PWA 安全上下文要求。

核心测试：安装 Node.js 后在项目目录运行 `node tests/core.cjs`。浏览器测试：临时安装 `npm install --no-save playwright`，再 `npx playwright install chromium`，运行 `node tests/browser.cjs`。也可用环境变量 `BROWSER_PATH` 指定本机 Chromium/Edge 可执行文件。测试自带临时本机静态服务，完成后自动关闭；部署无需这些工具或依赖。

目标为近期安卓 Chrome、iPhone Safari。当前未执行真实安卓和 iPhone 设备测试，详情见测试报告。
